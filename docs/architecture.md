# 动态模式架构

AstrBot事件 → 会话权限和每会话锁 → 判断是否需要新题 → 模型选题 → Bangumi核对 → 模型编写5/7/5 → Emoji结构校验 → 持久化生成题 → 状态机开局。

普通猜测、提示和揭晓不调用生成模型，答案和提示在出题时冻结。题面与判题分离；独立主持引子默认关闭。生成响应不注入普通聊天历史，也不把完整题目或答案传给后续聊天模型。

运行库dynamic-game.db的questions表保存生成题和来源ID，state保存会话进度，handled保存有限消息ID。历史题只供恢复和近期避重，新题必须有新生成的prepared_question，不允许自动选择历史缓存作为替代。

生成发生在SQLite事务之外，整轮有超时；校验成功后才登记并开局。每会话异步锁覆盖生成和发送，状态去重仍由数据库事务保护。断线/发送与数据库提交不构成分布式事务，不承诺恰好一次送达。

Bangumi访问可配置专用HTTP代理，不改变聊天模型的连接。运行环境负责保证代理可达；公开插件不绑定具体服务器地址或私人账号。
