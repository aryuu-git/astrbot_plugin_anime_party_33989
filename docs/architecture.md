# 架构与边界

```text
AstrBot事件 → 允许会话/定向消息检查 → 每会话异步锁
  → GameService路由 → SQLite事务：去重 + 游戏状态机 + 固定文案
  → 可选AI引子 → 停止后续聊天处理 → 发送结果
```

game/不依赖AstrBot、Apeiria工作区、Windows或外部服务。每次事务建立独立状态机实例，避免失败回滚后内存状态残留；不同会话按完整UMO隔离。SQLite事务阻止并发抢答产生多个获胜者。

消息ID去重最多保留4096条，跨重启有效；超过保留窗口的旧ID不保证识别，缺少平台消息ID时不能提供稳定投递去重。没有全局永久历史、用户画像或排行榜。

每个会话的适配层锁覆盖状态变更、可选AI及发送，保持该会话内回复顺序。超时检查复用同一把锁，并在数据库内再次检查当前状态。超时检查默认每30秒一次；迟到猜测也检查真实截止时间。

AI只生成40字以内引子，输入仅事件类型和提示序号。出题、判题、提示文本、揭晓内容和状态不由模型改变；引子校验拒绝已知答案别名及规则/判题字样，失败回退固定文案。通用模型的自由表达仍需实际体验，确定性游戏信息始终附加在后。

运行时不会读取磁盘人格目录，不额外保存模型密钥。可选表达通过AstrBot当前会话provider与persona解析器获取配置；兼容性需在目标版本验证，失败降级。

插件消费游戏消息后stop_event，普通消息放行。该行为也可能让后续记忆/观察插件看不到已消费的游戏消息；这是显式事件边界，并不代表所有优先级更高的监听器都可撤销。
